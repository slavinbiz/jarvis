# Карта нейрозавода — архитектура оркестратор+субагенты

> Источник: бонус трансляции Ледовских, https://platform.aibasis.ru/karta_neurozavoda (прочитано вживую 17.08.2026 через WebFetch)

## Концепция

Один оркестратор (я, Jarvis) управляет системой узкоспециализированных субагентов. Оркестратор принимает задачу, делит её между субагентами, собирает и проверяет результат, отдаёт владельцу с допущениями и следующим шагом.

**Ключевое правило безопасности:** субагенты не имеют права на финальные действия — отправку писем, публикацию, изменение данных. Финальное действие — всегда оркестратор, после подтверждения владельца (кроме явно согласованных автопусков, как дайджест @santex_s_ai по субботам).

## 5 типовых ролей

| Роль | Зона ответственности | Выход | Скиллы |
|---|---|---|---|
| Исследователь | ищет факты, сравнивает источники, фиксирует неизвестное | справка | web research, fact check |
| Контент-агент | превращает факты в контент разных форматов | черновик | copywriting, редактура |
| Агент продаж | квалифицирует запрос, готовит КП и следующий шаг | предложение | документы, работа с текстом |
| Операционный агент | ведёт задачи, статусы, таблицы, напоминания, дедлайны | порядок | документы, spreadsheets |
| Контролёр | проверяет факты, формат, риски, соответствие задаче | вердикт | QA для всех сфер |

## Пошаговый план создания субагента

1. Начать с 2 ролей, не с десяти
2. Определить одну задачу и ожидаемый результат
3. Назначить оркестратора — он отвечает за план и финальную сборку
4. Создать субагента — одна роль, входные данные, формат ответа
5. Ограничить доступ — только нужные данные и минимальные права
6. Добавить контроль — контролёр проверяет факты/соответствие
7. Сохранить удачную цепочку как шаблон для следующих запусков

## Шаблон командировки оркестратору (пример — запуск вебинара)

```
Ты — агент-оркестратор. Управляй системой субагентов:
Подготовь запуск вебинара на тему [тема] для [аудитория].
Делегируй:
1) исследователю — боли и вопросы аудитории;
2) контент-агенту — пост и письмо;
3) агенту продаж — оффер и CTA.
После этого передай всё контролёру, попроси найти неподтверждённые
обещания и собери финальный план.
Не выдавай результат, пока не перечислишь допущения и следующий шаг.
```

## Практический пример (Схема 02)

1. Оркестратор принимает задачу "Запусти вебинар"
2. Разбивает работу между субагентами
3. Параллельно: исследователь → боли аудитории, контент-агент → пост и письмо, продажник → оффер и CTA
4. Контролёр проверяет все материалы
5. Владелец получает: темы, контент, оффер, допущения, следующие шаги
