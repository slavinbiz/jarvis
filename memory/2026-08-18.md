## Сессия 1 (Windows, 09:xx)
Тема: голосовые Джарвису в Telegram не распознаются

### Сделано
- Диагностировал через systematic-debugging: root cause — после переезда с Beget на Fornex (08.08) распознавалку голоса не перенесли вообще. В `/home/agent/.agent/.env` не было ни `DEEPGRAM_API_KEY`, ни установленного Whisper — бот молча уходил в fallback-сообщение "Не получилось распознать" (без логов, поэтому в journalctl ничего не было видно)
- Попытался поставить Whisper локально (`apt install ffmpeg` — ок) — pip не был установлен, поставил `python3-pip`, запустил `pip install openai-whisper`
- **Инцидент:** pip начал тянуть полный GPU/CUDA-набор torch (nvidia-cuda-*, triton, ~сотни МБ) на сервере без GPU. Диск Fornex — всего 9.8GB, свободно было 5.4GB → скатилось до 702MB (93% занято) прежде чем заметил и убил процесс (`pkill -9 -f pip`). Почистил `pip cache purge` (+455MB) и `apt clean` — вернул 1.3GB свободных
- Вячеслав выбрал вместо Whisper — Deepgram (не грузит диск сервера). Зарегистрировался, прислал API-ключ, вписал в `.env`, перезапустил `agent-bot` — сервис активен, ключ подхвачен

### Решения
- **Whisper на Fornex НЕ ставим** — диск слишком маленький (9.8GB) для torch+CUDA зависимостей, риск уронить продакшен-бота на этом же сервере. Deepgram — постоянное решение для голосовых
- Если когда-то понадобится офлайн-распознавание — делать на отдельном сервере с бóльшим диском, не на Fornex

## Сессия 2 (Windows) — крипто-бот: баг `ema_pullback.evaluate_tracking` (из бэклога 17.08)

### Сделано
- systematic-debugging: root cause — рассинхронизация деплоя, не отсутствие кода. Сервис `crypto-bot` на TimeWeb стартует как `/usr/bin/python3 /root/crypto_bot.py` (WorkingDirectory=`/root`), значит импортирует `/root/ema_pullback.py`
- При доработке pullback-трекинга 21-23.07 кто-то задеплоил полный свежий набор файлов в **побочную папку `/root/crypto_bot/`** вместо `/root/` — там всё было рабочее, но не подключено к systemd. `/root/crypto_bot.py` продолжали обновлять на месте (до 3.08), а `/root/ema_pullback.py` остался версией от 23.07 07:49 (за 6 часов до того как в тот же день добавили `evaluate_tracking`) — отсюда `AttributeError` 19к+ раз с 3 августа
- Сверил все три модуля (`crypto_bot.py`, `ema_pullback.py`, `ema_trend.py`) между `/root/`, локальным репо и папкой `/root/crypto_bot/` — расхождение нашлось только в одном файле
- Задеплоил актуальный `ema_pullback.py` из локального репо в `/root/` на TimeWeb, `systemctl restart crypto-bot`
- Переименовал сбивающую с толку папку в `/root/crypto_bot.OLD_UNUSED_20260723` (не удалил — на случай если понадобится история)
- Проверил 3 минуты логов после рестарта (по номеру строки последнего "Application started", не по grep времени без даты — первая попытка проверки дала ложный `FOUND` из-за совпадения времени с прошлыми днями) — ошибка не повторилась, трекинг-цикл (~раз в минуту) прошёл чисто

### Решения
- Впредь при ручном scp-деплое на TimeWeb — деплоить **все изменённые модули разом**, не только `crypto_bot.py`, и **строго в `/root/`** (там реально работает WorkingDirectory systemd-юнита), не в подпапки
