## Сессия 4
Тема: личный VPN на Fornex через WireGuard (вместо s-ui/Hysteria2 как на TimeWeb) — сервер поднят, клиент на Windows не подключается

### Сделано
- Вячеслав сам поставил `wg-quick@wg0` на Fornex (213.193.196.125:51820, подсеть 10.0.0.0/24, NAT/MASQUERADE eth0, ip_forward=1) — сервер полностью рабочий, подтверждено: хендшейки проходят, `wg show` видит пира, трафик через iptables FORWARD идёт
- Клиентский конфиг `C:\Users\User\Desktop\client.conf` — сначала `AllowedIPs = 0.0.0.0/24` (баг, реально не туннелировал интернет-трафик, IP-чекер показывал Россию) → поправили на `0.0.0.0/0`
- После правки — интернет на Windows полностью пропал (браузеры не грузят). Диагностика: `ping 1.1.1.1` и `nslookup` — 100% потерь. `tcpdump` на сервере (2 захвата по 45/90 сек на wg0, icmp+udp/53) — 0 пакетов дошло с клиента вообще
- Важное открытие: эта Windows-машина и есть машина Вячеслава — не нужно просить его гонять ping через переписку, можно проверять `route print`/`ipconfig` прямо через Bash-тул локально
- `route print` показал: **ни одного маршрута через WireGuard-адаптер** (ни 0.0.0.0/1+128.0.0.0/1 override, ни даже 10.0.0.0/24) — дефолтный маршрут с метрикой 0 держит `sing-tun Tunnel` (Happ)
- `Get-NetIPAddress` показал: Wintun-адаптер («Wintun Userspace Tunnel») вообще без IPv4-адреса — Windows не сконфигурировал сеть, хотя GUI показывал «Подключен»
- На машине куча параллельных VPN/туннельных адаптеров: Outline (`outline-tap0`), WireSock, Happ (`happ-tun`/`sing-tun`), забытый `TAP-Windows Adapter V9`, плюс WireGuard/Wintun — подозрение на конфликт вокруг общего Wintun-драйвера
- Проверили сервисы (`Get-Service`) — есть только `WireGuardManager`, нет отдельного `WireGuardTunnel$client` (штатный сервис, который реально поднимает адаптер) — само по себе подозрительно, но решающую причину нашли в журнале приложения
- **Журнал WireGuard (скрин от Вячеслава)** дал точный диагноз: `Timed out waiting for device query` → `Failed to setup adapter (problem code: 0x1F, ntstatus: 0xC00002F0)` → `Unable to create network adapter: Error creating adapter` — драйвер Wintun физически не может создать новый адаптер, даже запуская WireGuard от администратора. Классический сценарий — залипшее состояние драйвера в ядре из-за конфликта нескольких VPN-инструментов на одном Wintun

### Решения
- Личный VPN переезжает на Fornex/WireGuard (сервер полностью готов и рабочий), но клиент на Windows пока не подключается — проблема не в конфиге и не в сервере, а в Windows-драйвере Wintun
- Эта рабочая машина = машина Вячеслава — для будущей диагностики сети можно проверять `route print`/`ipconfig`/`Get-NetIPAddress` напрямую, не просить пользователя присылать скриншоты команд
