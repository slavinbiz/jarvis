# Генерация картинок к постам для Jarvis — дизайн

**Дата:** 2026-08-08
**Статус:** утверждено, готово к плану

## Проблема

Jarvis (Telegram-бот `@dgarvise_bot`, Fornex) помогает писать посты для канала `@santex_s_ai`, но не может сгенерировать к ним иллюстрацию. Картинки под посты Вячеслав сейчас не делает вообще.

## Решение

Добавить Jarvis знание (`knowledge/image-generation.md`), как генерировать картинку через бесплатный сервис Pollinations.ai и прикреплять её к ответу в чате. Код бота (`bot/index.js`, `bot/secrets-menu.js`) не меняется — вся логика на стороне промпта/знания, исполняется самим Jarvis через Bash-инструмент Claude Code CLI.

### Почему без изменений кода бота

- `~/.agent/bot/` на сервере — read-only зона для агента (правило CLAUDE.md, чтобы Jarvis не сломал сам себя)
- Команда `/update` перезаписывает `bot/` из апстрима `github.com/Ntmib/jarvis-architect` — любой кастомный код в `bot/` слетит при следующем обновлении
- `knowledge/` и `memory/` переживают `/update` (подтверждено `knowledge/update-guide.md`: «Все ваши данные... сохранятся — обновляется только код бота») и синхронизируются через `git pull origin main`, который Jarvis выполняет в начале каждой сессии (шаг 0 в CLAUDE.md)
- У Jarvis уже есть готовый механизм доставки файла в чат — тег `[ФОТО: путь]`, который бот парсит и отправляет (`extractMediaTags`/`sendMediaItem` в `bot/index.js`). Ничего дополнительного строить не нужно

### Сервис генерации

**Pollinations.ai**, бесплатно, без API-ключа и без карты.

```
GET https://image.pollinations.ai/prompt/{urlencoded_prompt}?width=1280&height=720&model=flux&nologo=true
```

- Ответ — сразу байты картинки (JPEG), никакого JSON-обёртывания
- Анонимный доступ: лимит 1 запрос / 15 секунд — для разовой генерации к посту достаточно
- `nologo=true` уменьшает вероятность водяного знака, но не гарантирует его отсутствие без регистрации
- Модель `flux` — универсальная, без реалистичного рендера текста (модели вообще плохо рисуют читаемый текст — промпт не должен на него рассчитывать)

### Формат knowledge/image-generation.md

Документ должен содержать (в стиле остальных файлов `knowledge/`, короткий и практичный):

1. Когда использовать — по прямой просьбе в чате («сделай картинку к посту», «сгенерируй иллюстрацию»), НЕ автоматически на каждый пост
2. Как составить промпт — на английском, по смыслу поста, без расчёта на читаемый текст/логотипы на картинке, стиль можно варьировать (иллюстрация/фото/минимализм) по контексту разговора
3. Команда curl:
   ```
   curl -sL -o /home/agent/workspace/.media/generated_<timestamp>.jpg \
     "https://image.pollinations.ai/prompt/<urlencoded_prompt>?width=1280&height=720&model=flux&nologo=true"
   ```
   — путь сохранения в `workspace/.media/` (та же папка, что и для входящих медиа от пользователя)
4. Проверка — curl должен завершиться без ошибки и файл должен быть непустым (`-f` флаг curl + проверка размера файла); если не получилось — сказать об этом прямо, не выдумывать, что картинка готова
5. Прикрепление к ответу — тег `[ФОТО: /home/agent/workspace/.media/generated_....jpg]` в финальном сообщении
6. Заметка про водяной знак и что при желании можно завести бесплатный Seed-аккаунт Pollinations (email, без карты) для более чистых картинок и лимита раз в 5 сек

## Что НЕ входит в эту итерацию

- Автопубликация в канал `@santex_s_ai` — её сейчас нет вообще (Вячеслав постит сам), не строим
- Regenerate-кнопки, инлайн-выбор стиля, история сгенерированных картинок — избыточно для одного пользователя и редких постов
- Polza API / платный вариант — оставлен как задокументированная альтернатива на будущее (реферальная ссылка уже сохранена в memory/2026-08-08.md), не реализуется в этой итерации
