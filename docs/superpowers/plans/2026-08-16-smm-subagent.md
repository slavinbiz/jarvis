# SMM-субагент для @santex_s_ai — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Делегировать подготовку постов для @santex_s_ai именованному субагенту `smm`, запускаемому по расписанию бота, с публикацией по матрице прав (дайджест — сам, продажа/практика — через согласование Вячеслава).

**Architecture:** Новый файл `.claude/agents/smm.md` определяет субагента-специалиста (доступен через `Agent(subagent_type:"smm")`). Существующий планировщик Jarvis-бота (`schedules.json`, уже работает в проде — код не трогаем) по расписанию запускает headless-сессию Claude с промптом-инструкцией: продиспетчерить `smm`, получить черновик, и либо опубликовать сразу (дайджест), либо сохранить как pending-запись и запросить "ок" у Вячеслава (продажа/практика). Хендофф подтверждения между сессиями — через файл `workspace/.smm-pending.json`: следующая обычная сессия, когда Вячеслав подтверждает, читает файл и публикует.

**Tech Stack:** Claude Code custom subagents (`.claude/agents/*.md`), существующий scheduler бота (`bot/index.js` — только чтение, не модифицируем), `bot/scripts/manage-schedule.js` (CLI для CRUD над `schedules.json`, уже задеплоен на Fornex), Telegram Bot API (curl), Pollinations.ai для картинок.

**Spec:** `docs/superpowers/specs/2026-08-16-smm-subagent-design.md`

## Global Constraints

- Никогда не упоминать VPN-бот `@djarvisvpn_bot` ни в одном публичном контенте (правило из MEMORY.md)
- Формат постов — HTML для Telegram, НЕ markdown; жирный только в заголовке (правило `santex-post-writer`)
- `~/.agent/bot/` (продакшн-код бота на сервере) — read-only зона, эта задача НЕ трогает `bot/index.js` и другой код бота, только данные (`schedules.json` через существующий `manage-schedule.js`) и конфиг-файлы Claude Code
- Продажа и (пока) практика публикуются только после явного "ок" Вячеслава — не автоматически
- Регистрация реальных cron-расписаний на проде (Task 4) и первое включение (Task 5) — это изменения живого продакшна с публичным Telegram-каналом, требуют явного разрешения Вячеслава перед выполнением, не просто перед коммитом

### Pending-черновик — хендофф между сессиями

Задачи по расписанию выполняются в изолированной headless-сессии (без
истории переписки с Вячеславом). Когда пост требует согласования, эта
сессия не может дождаться ответа Вячеслава сама — вместо этого:

1. Черновик сохраняется в `/home/agent/workspace/.smm-pending.json`
   (формат — см. ниже). Если файл уже существует с другой pending-записью
   — не перезаписывать, сообщить Вячеславу о конфликте
2. Вячеславу отправляется черновик целиком + "Публикую после твоего 'ок'"
3. Когда в ЛЮБОЙ следующей сессии Вячеслав отвечает подтверждением
   ("ок", "публикуй", "го", "да" — в контексте последнего присланного
   черновика) — прочитать `.smm-pending.json`, опубликовать через Bot API
   (см. ниже), удалить файл, подтвердить публикацию
4. Если Вячеслав просит правки вместо "ок" — поправить текст в файле,
   прислать заново, снова ждать подтверждения

Формат `.smm-pending.json`:

```json
{
  "id": "practice-2026-08-18",
  "type": "practice",
  "text": "<b>Заголовок</b>\n\nТекст поста...",
  "image": null,
  "createdAt": "2026-08-18T15:00:00+03:00"
}
```

### Публикация через Bot API

Токен `@dgarvise_bot` — в `/home/agent/projects/santex-poster/credentials.json`
(поле `bot_token`), бот уже админ канала. Никогда не печатать сам токен в
чат.

```bash
TOKEN=$(node -e "console.log(require('/home/agent/projects/santex-poster/credentials.json').bot_token)")

# без картинки
curl -sf -X POST "https://api.telegram.org/bot${TOKEN}/sendMessage" \

  -F photo=@"<путь_к_картинке>"
```

Проверить в JSON-ответе `"ok":true`. Если `false` — не считать пост
опубликованным, разобраться в причине (`description` в ответе) прежде

```
